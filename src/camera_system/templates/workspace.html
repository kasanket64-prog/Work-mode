Command Line & Docker Quickstart

Copy and run commands from the repository root (`Work-mode/`).

Local Workspace Server
.venv\Scripts\camera-workspace.exe --port 8780 --warm-worker --strict-uploads
Kalman Video Pipeline
.venv\Scripts\camera-video.exe --video clip.mp4 --tracker kalman --stride 5 --output outputs\clip.jsonl
Calibration Benchmark
.venv\Scripts\camera-benchmark.exe outputs\demo\session.jsonl --truth outputs\demo\truth.json --output-dir outputs\bench
Docker Compose (CPU / GPU)
docker compose up --build

Frequently Asked Questions

Do I need to connect a camera?

No. Start by uploading a video or image in Analyze Studio. Live camera indexes and authenticated RTSP/HTTP streams are supported via the `camera-video` CLI (`--live-buffer`, `--reconnect-attempts`, `--stream-credentials-env`).

Where does my footage go?

All uploads and results stay on your machine inside the local workspace directory and SQLite database (`fieldnote.db`) until you delete them. Nothing is published or uploaded externally.

Does it analyze the entire recording?

Videos are sampled at your selected stride up to the frame limit. Always check Coverage & processing details on the card—completing a 30-frame quick look does not imply full-clip coverage.

How reliable are the findings?

Findings are pretrained model predictions and rule-based temporal event candidates, not verified facts. Review the source frame/video and verify annotations with `camera-benchmark` before drawing conclusions.

How fast does analysis run?

Runtime depends on CPU/CUDA hardware and sample limit. With `--warm-worker` enabled, loaded weights remain cached across consecutive jobs so startup overhead only happens once.

What can I export?

Download raw JSONL session outputs directly from Workspace. Inside Review, save verdicts to SQLite, export full session JSON, draw zones & replay rules, and evaluate ground-truth metrics live.
