# Compare detection on your images

Run from the repository root after installing the detection extra:

```powershell
.\.venv\Scripts\python.exe scripts/compare_detection.py path/to/day.jpg path/to/night.jpg --output outputs/my-comparison
```

Use a new output directory. The script uses cached YOLO11n weights (downloads on first use), runs on CPU, and compares:

1. Baseline: 640 pixels, at most 20 detections.
2. Crowd: 640 pixels, at most 60 detections.
3. Detail: 1280 pixels, at most 60 detections.

Confidence and overlap thresholds remain fixed. Each setting gets a warm-up; timings cover one following detection call, not the entire camera pipeline. `comparison.md` and `comparison.json` contain counts/settings/timings. Per-image JSON and HTML contain box overlays with the source preview. No relation or pose predictions are generated by this comparison.

These are unlabeled diagnostic runs, not precision/recall benchmarks. Extra boxes may be true detections, duplicates, or false positives. Label the visible objects with a consistent policy for tiny/occluded objects, then score matched predictions before promoting a setting. Use separate images for final validation rather than tuning and reporting on the same samples.

To try the optional detail profile in the existing pipeline:

```powershell
.\.venv\Scripts\camera-relations.exe --image path/to/image.jpg --detect --detector-config configs/detector-detail.toml --config configs/camera.toml --include-preview --output outputs/detail-result.json
```

The default remains unchanged. Relation inference on more objects can be substantially slower. Uploaded samples and generated previews remain under ignored `outputs/`; do not commit or redistribute third-party sample media without appropriate rights. Existing watermarks are preserved. Video tracking evaluation requires an accessible video file, not still images.

## Video diagnostics

### Office trial profile

`configs/detector-office.toml` uses a 40-object cap at 1280-pixel inference resolution. It retains the resolution used in the detail comparison, which averaged 30 detections per sampled office frame. This is a trial setting, not a verified accuracy improvement. The baseline stays at 20 and the crowded-scene detail profile stays at 60.

```powershell
.\.venv\Scripts\camera-video.exe --video "path/to/office.mp4" --detector-config configs/detector-office.toml --config configs/camera.toml --stride 7 --max-frames 12 --include-preview --analyze-people --output outputs/office-40.jsonl
```

Use a new output filename for each run. This command runs the full relationship pipeline; the diagnostic timings below cover detection and tracking only. `configs/camera.toml` allows 40 regions so it does not truncate the office profile back to 20. Combining the 60-object detail detector with this camera configuration still yields an effective limit of 40; the standalone comparison scripts do not run the relation model.

This office clip is 25 FPS: stride 7 gives 0.28-second observations, within the person motion estimator's 0.25–2 second interval. Choose stride according to the FPS of other videos. Twelve observations cover timestamps 0–3.08 seconds, not the whole clip.

Verified on 6 October 2026 with detector, IoU tracking, RelateAnything, temporal reasoning, pose, person observations and previews enabled: all 12 frames completed, with 27–35 objects per frame (mean 30.33). No frame reached the 40-object cap. Mean per-frame processing was 2.75 seconds; total startup and processing took 67.14 seconds on CPU. This does not meet live throughput at 0.28-second sampling. There were 150 person observations across frames, including 114 motion estimates; these are repeated observations, not unique people. The model returned 600 relation candidates in total; none met temporal confirmation criteria, and no events were emitted. This short sample cannot validate the 30-second unattended-object rule or establish accuracy. Saved relation endpoints, frame limits, previews and successful completion were checked. Local artifacts: `outputs/office-40-verified-20261006.jsonl`, `outputs/office-40-verification.json`, and `outputs/office-40-review.html`.

### Compare baseline and detail

```powershell
.\.venv\Scripts\python.exe scripts/compare_video.py path/to/clip.mp4 --output outputs/video-comparison
```

This compares the baseline and detail detector with the existing IoU tracker. By default it reads the first 12 sampled frames at approximately four frames per second (about 2.6–2.8 seconds). Increase `--max-frames` to cover more of a clip. Each profile resets tracking and uses the same frame indices. Source videos are read without modification; result previews stay in the output directory.

The report includes average detections, class observations, unique track IDs, single-observation tracks, previous-frame ID reuse, and warm detection/tracking time. Class observations sum detections across frames; they do not count distinct real-world objects. Track IDs may split or switch, so neither the track count nor ID reuse measures identity accuracy. Timing excludes decoding, previews, model startup, pose, relationships and events. Those latter three analyses are not run by this diagnostic script. Review overlays against the original clip and add labeled tracks before claiming an accuracy improvement.
